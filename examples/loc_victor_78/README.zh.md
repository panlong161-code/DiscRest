# Victor 73978，美国国会图书馆转录，30 秒

这个示例用来跑隆隆声、哼声、嘶声三级。录音本身是真实的；叠加在它上面的损伤量是已知的，
所以数字可核。

## 来源

美国国会图书馆 National Jukebox：Victor 73978，matrix B-28269。下载文件为
`master-mbrsrs-mbrsjukebox-jvm_victor_73978_01_b28269_01.wav`，44 100 Hz、16 bit PCM、
双声道、202.53 秒。`input.wav` 取 38.000–68.000 秒并下混为单声道——这一段是整条里电平最平的
（30 个 1 秒窗的变异系数 0.185）。

该录音在美国属于公有领域。本仓库不对美国以外的版权状态作任何主张。

## 交付文件里没有隆隆声，也没有哼声

这条转录是交付母带，不是原始转储。四个读数可以确认：

| 属性 | 实测 | 含义 |
|---|---|---|
| 声道 | 双声道，相关系数 1.000000，差值 ≈1 LSB | 声学录音是单声道，第二声道是复制 |
| 峰值 | 32 766 / 32 768 | 归一化到约 0 dBFS |
| 波峰因数 | 5.8 | 未处理的声学转录通常在 12 以上 |
| 99% 带宽 | 7 250 Hz | 声学录音的上限是 3–3.5 kHz |

低频在交付前已被滤掉：`rumble_ratio` 只有 0.0008，`hum_prominence` 只有 3.49，
而画像阈值分别是 0.08 和 8.0。下载到的文件里，这两级没有可处理的对象。

## `overlay.py` 加了什么

`overlay.py` 在这条转录上叠加三档损伤并写出 `input.wav`，每档的量都会列出。叠加前先把基底
压低 6 dB 以免削波；这个统一缩放会从下面所有比值里抵消。

| 级 | 模型 | 目标 | `input.wav` 实测 |
|---|---|---|---|
| 隆隆声 | 1/f 噪声，4 阶 Butterworth 35 Hz 低通，加 0.5556 Hz（33⅓ 转）偏心分量 | `rumble_ratio` 0.18 | 0.1781 |
| 哼声 | 50 Hz 加二次、三次谐波，分别 0、−3、−6 dB，带 ±0.01 Hz 慢漂 | `hum_prominence` 25 | 11.96 |
| 嘶声 | 白噪，2 阶 1 kHz 高通 | 相对基底 20 dB | — |

叠加隆隆声之后哼声从 25 掉到 11.96：低频噪声填满了 50 Hz 两侧的裙边，把谱线盖住了。
两项仍然都在阈值之上，`profile` 报 `low-frequency, mains-hum`。

因为基底保留着，误差信号是已知量，可以算出真 SNR。原始转录给不了这个，
这正是叠加存在的唯一理由。

## 这次运行做了什么

`run.yaml` 打开隆隆声、哼声、嘶声，关掉去咔嗒和去裂纹：转录没有脉冲类损伤，`click_count` 为 0。

| 量 | 值 |
|---|---|
| `rumble_ratio` 前 → 后 | 0.1781 → 0.0006 |
| `hum_prominence` 前 → 后 | 11.96 → 1.60 |
| 移除 RMS，隆隆声 / 哼声 / 嘶声 | 0.0643 / 0.0012 / 0.0171 |
| 泄漏，哼声 | share 0.3795，occupied 0.0000，未回退 |

哼声级的 share 已过 0.35 的线，但 `occupied` 是 0.0000，所以守卫没有回退它。这个例子正好说明
为什么守卫需要两个条件：只看 share，会把一个根本没动到乐音带的级判成泄漏。

## 嘶声级在这里是负结果

`dehiss` 把高频底噪压低了 3.4 dB，但 SNR 从 20.00 降到 15.32 dB。试过 30 组参数，最好的一组
也只涨 0.29 dB。原因在噪声估计：`dehiss` 取最安静的 15% 帧，而这一段是连续演奏、没有静音帧，
于是音乐被当成噪声估了进去。

在基底前面插入静音、噪声成分一个采样都不改，静音占比到 15% 时 SNR 由 −4.68 dB 转成
+2.57 dB 并饱和——正好等于 `noise_percentile` 的 15%。`dehiss` 需要可识别的安静帧；
连续演奏的转录没有，这也是它默认关闭的原因。

```text
python -m discrest verify examples/loc_victor_78
```
